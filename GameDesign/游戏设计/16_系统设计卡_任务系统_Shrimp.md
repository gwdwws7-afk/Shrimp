# 系统设计卡：任务系统（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Quest
关联 DDR-ID: `DDR-2026-03-24-10`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 为关卡推进提供明确目标、风险提示和奖励预期。
  - 将“做什么”与“为什么做”连接到战斗和成长闭环。
- 系统边界（与其他系统接口）:
  - 上游: 关卡流程、据点/事件、Boss Gate。
  - 下游: 经验/珍珠/货币发放、失败判定、结算展示、存档恢复。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 我不仅在清怪，而是在执行有明确目的的作战任务，并且每次完成都有可感知成长回报。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 接收目标 -> 完成一个阶段条件（击杀/到达/保护）-> 获得进度与反馈。
- 3 分钟循环:
  - 事件任务链推进 -> 阶段目标切换 -> 风险上升 -> 完成后进入下一战斗节点。

## 4) 关键规则与约束

- 规则 1:
  - 每关必须有“主线目标 + 至少 1 个可感知事件目标”，避免纯清怪。
- 规则 2:
  - 任务类型需包含主线/支线/挑战三层，奖励权重与风险匹配。
- 规则 3:
  - 任务失败条件必须可解释并在 UI 中可追溯。
- 关键约束（性能/输入/资源/时序）:
  - 任务状态恢复需与运行时一致（进度、阶段、计时器）。
  - Boss 关卡需强制存在 Boss 目标耦合项。

## 5) 决策点与风险回报

- 主要决策点:
  - 先推主线还是处理中途挑战目标。
  - 是否冒险追求高奖励挑战目标。
- 失败代价:
  - 任务失败会造成奖励折损与节奏回退。
- 成功收益:
  - 更高成长回报、更清晰推进节奏、战斗目标感更强。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 任务阶段切换、关键目标受损、完成结算须有明显状态反馈。
- 音频反馈:
  - 任务完成、失败、阶段更新采用分层提示音。
- UI 提示:
  - 任务追踪仅显示当前关键步骤，避免信息过载。
- 失败后纠偏提示:
  - 明确告知失败条件触发源和下一次建议优先级。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - 前两关用主线目标引导玩家理解“推进-结算-成长”回路。
- 第一次失败学习点:
  - 玩家学会优先处理“保护/限时”类高风险目标。
- 中后期进阶点:
  - 在复合任务下做风险收益权衡，兼顾效率与安全。

## 8) 核心参数区间（最小/推荐/最大）

- 单关可见主线目标数（条）: `1 / 1-2 / 3`
- 单关挑战目标数（条）: `0 / 1 / 2`
- 任务失败容错窗口（秒）: `0 / 3-5 / 8`
- 任务奖励倍率（主线/挑战）: `1.0 / 1.15-1.3 / 1.5`

## 9) 验收标准（量化）

- 指标 1（流程完整性）:
  - Boss 关卡任务链包含 Boss 目标耦合项，且可通过专项回归验证。
- 指标 2（状态一致性）:
  - 任务恢复后阶段、进度、计时器一致，无明显状态错位。
- 指标 3（奖励闭环）:
  - 任务完成奖励正确路由到经验与钱包链路，且与权重规则一致。
