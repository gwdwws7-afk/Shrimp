# 系统设计卡：手柄支持（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Input
关联 DDR-ID: `DDR-2026-03-24-13`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 玩家可用手柄完成战斗、菜单、结算全流程，不因输入设备切换而降级。
  - 玩家始终看到与当前设备一致的操作提示与 action label。
- 系统边界（与其他系统接口）:
  - 上游: 统一输入层、动作绑定配置、设备检测。
  - 下游: HUD 提示、技能栏按键提示、菜单提示、调试提示统一显示。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 我接上手柄就能顺畅玩完整个游戏，不需要猜按键，也不会遇到错配提示。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 读取当前提示 -> 输入动作 -> 获取一致反馈（战斗与 UI）。
- 3 分钟循环:
  - 设备切换或场景切换后，提示与绑定保持同步，无操作断层。

## 4) 关键规则与约束

- 规则 1:
  - 核心战斗动作必须同时具备键鼠和手柄绑定。
- 规则 2:
  - UI 提示与输入层 action label 必须一一对应，不得出现旧键残留。
- 规则 3:
  - 设备切换后提示刷新需在可接受时延内完成。
- 关键约束（性能/输入/资源/时序）:
  - 使用统一输入层，不再回退 legacy 直接按键判定。
  - 场景预制体中的快捷键提示必须通过审计门禁。

## 5) 决策点与风险回报

- 主要决策点:
  - 哪些提示常驻，哪些按上下文触发，如何兼顾可读性与不打扰。
- 失败代价:
  - 键位错配会直接造成误操作和挫败。
- 成功收益:
  - 全流程可玩性提升，输入学习成本降低，设备切换更平滑。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 所有关键动作提示显示当前设备对应标签（键鼠/手柄）。
- 音频反馈:
  - 关键系统切换与菜单确认有稳定反馈，减少输入不确定性。
- UI 提示:
  - 技能栏、HUD 提示、主菜单副标题等统一调用输入层 label。
- 失败后纠偏提示:
  - 当检测到缺失绑定时，显示可执行修复提示而不是静默失败。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - 第一关内让玩家完成“移动-攻击-技能-交互”全套手柄动作。
- 第一次失败学习点:
  - 玩家可从统一提示中确认正确按法并快速纠偏。
- 中后期进阶点:
  - 高压战斗下仍能稳定读取技能、系统快捷和菜单操作提示。

## 8) 核心参数区间（最小/推荐/最大）

## 9) 验收标准（量化）

- 指标 1（绑定完整性）:
  - 核心战斗与系统动作具备手柄绑定并通过专项回归。
- 指标 2（提示一致性）:
  - 主菜单/HUD/技能栏等提示与输入层 action label 一致。
- 指标 3（场景稳定性）:
  - 场景级输入绑定审计无 mismatch，门禁通过。
