# 系统设计卡：音效与特效（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/AudioVFX
关联 DDR-ID: `DDR-2026-03-24-19`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 通过音画反馈准确感知命中、受击、破防、技能与事件状态。
- 系统边界（与其他系统接口）:
  - 上游: 战斗事件、技能事件、据点事件、Boss 事件。
  - 下游: SFX 播放、VFX 触发、屏幕后处理反馈。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 每次关键操作都有清晰反馈，战斗更“有手感”且可读。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 触发动作 -> 命中/受击反馈 -> 形成下一步决策。
- 3 分钟循环:
  - 多事件叠加下依然能依靠音画区分关键威胁与窗口。

## 4) 关键规则与约束

- 规则 1: 核心战斗事件必须有一一映射的 SFX/VFX 反馈。
- 规则 2: 高优先事件反馈不得被低优先效果覆盖。
- 规则 3: 反馈风格与强度需可分层（普通/关键/高光）。
- 关键约束:
  - 当前资源缺口较大，优先保证功能反馈链完整。
  - 在资源不足时使用 fallback 方案保持可用性。

## 5) 决策点与风险回报

- 主要决策点: 先补“可读性关键反馈”还是“风格化表现反馈”。
- 失败代价: 打击感弱、信息不清、战斗读招困难。
- 成功收益: 手感增强，策略判断效率提升。

## 6) 反馈与可读性策略

- 视觉反馈: 命中/破防/终结/危险预警必须高区分度。
- 音频反馈: 攻击层级和关键事件有差异化提示。
- UI 提示: 与 HUD 提示语义一致，避免重复噪声。
- 失败纠偏: 缺资源时明确 fallback，不静默失效。

## 7) 学习曲线与失败学习点

- 入门: 先建立命中与受击基础反馈认知。
- 首次失败: 能通过反馈识别“被什么机制压制”。
- 进阶: 在高密度效果中仍可读关键窗口。

## 8) 核心参数区间（最小/推荐/最大）

- 核心事件音画覆盖率（%）: `70 / 90 / 100`
- 关键事件优先级冲突（条）: `0 / 0 / 1`
- fallback 命中率（%）: `90 / 100 / 100`

## 9) 验收标准（量化）

- 指标 1: 技能与核心战斗反馈资源映射表完整。
- 指标 2: 关键事件（命中/受击/破防/终结）反馈链可验证。
- 指标 3: 资源缺口通过 fallback 保证运行稳定。
