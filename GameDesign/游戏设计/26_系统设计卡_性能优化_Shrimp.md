# 系统设计卡：性能优化（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Performance
关联 DDR-ID: `DDR-2026-03-24-20`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 在高同屏敌人数场景中保持稳定帧时间与输入响应。
- 系统边界（与其他系统接口）:
  - 上游: AI 更新频率、波次密度、VFX 投放、对象池策略。
  - 下游: 实际帧率、帧时间抖动、GC 分配、可玩稳定性。

## 2) 玩家核心幻想

- 玩家在大规模战斗中仍能获得顺滑、可控的操作体验。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 高压战斗 -> 帧时间稳定 -> 输入与反馈无明显迟滞。
- 3 分钟循环:
  - 波次与事件升压下持续保持性能门禁阈值。

## 4) 关键规则与约束

- 规则 1: 距离分级更新（Full/Simplified/Minimal）不破坏行为语义。
- 规则 2: 批量更新与节流优先控制 CPU 峰值。
- 规则 3: GC 分配需长期维持低抖动。
- 关键约束:
  - 100-150 同屏是必须验证场景。
  - 真机长时样本需持续扩展。

## 5) 决策点与风险回报

- 主要决策点: 画面表现保真 vs. 稳定帧时间。
- 失败代价: 输入迟滞、读招失败、体感割裂。
- 成功收益: 大规模战斗可持续、性能门禁可预测。

## 6) 反馈与可读性策略

- 视觉反馈: 性能优化不应牺牲关键读招反馈。
- 音频反馈: 高负载时避免关键音效丢失。
- UI 提示: 压测数据和门禁结果可追溯展示。
- 失败纠偏: 对失败门禁给出明确瓶颈维度（AI tick/GC/frame）。

## 7) 学习曲线与失败学习点

- 入门: 建立基线场景与指标认知。
- 首次失败: 识别是“内容过载”还是“更新策略问题”。
- 进阶: 在不同关卡密度下维持稳定阈值。

## 8) 核心参数区间（最小/推荐/最大）

- 同屏活跃敌人（人）: `100 / 120-150 / 170`
- p95 帧时间（ms）: `<=12 / <=9 / <=7`
- GC p95（B）: `0 / 0 / <=256`
- AI 更新吞吐（ops/s）: `400 / 550 / 700`

## 9) 验收标准（量化）

- 指标 1: P4 压测门禁通过（100/150 同屏）。
- 指标 2: 长时压测门禁通过且关键指标稳定。
- 指标 3: 全量门禁中性能相关子集持续通过。
