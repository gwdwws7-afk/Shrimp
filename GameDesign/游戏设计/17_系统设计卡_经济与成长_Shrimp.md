# 系统设计卡：经济与成长（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Economy
关联 DDR-ID: `DDR-2026-03-24-11`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 通过战斗、任务、关卡结算获得可持续成长，形成长期 build 目标。
  - 在资源获取与消耗之间做取舍，而非单一路径堆叠。
- 系统边界（与其他系统接口）:
  - 上游: 战斗掉落、任务奖励、关卡结算、章节难度。
  - 下游: 经验等级、天赋点、珍珠与货币、商店购买、里程碑奖励。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 我每一局都有成长收益，且能逐步形成自己的战斗构筑路线。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 战斗/任务获取资源 -> 即时收益反馈（经验/掉落）-> 做短期消耗决策。
- 3 分钟循环:
  - 关卡阶段奖励 -> 天赋/珍珠配置 -> 形成下一阶段更强战术能力。

## 4) 关键规则与约束

- 规则 1:
  - 奖励叠乘链需可解释、可审计，避免黑箱收益。
- 规则 2:
  - 经济增长曲线必须与章节难度同步，避免中后期失速或爆仓。
- 规则 3:
  - 商店与库存扣费必须原子化，禁止“扣币不入包”。
- 关键约束（性能/输入/资源/时序）:
  - 配置表结构完整且范围合法（含难度表长度与非负校验）。
  - 奖励路由在任务/关卡/里程碑场景下保持一致。

## 5) 决策点与风险回报

- 主要决策点:
  - 资源投入即时战力还是长期成长节点。
  - 商店消费时机与关卡风险储备平衡。
- 失败代价:
  - 资源错配导致战力断层，后续关卡压力显著升高。
- 成功收益:
  - 构筑逐步成型，提升战斗效率和稳定性。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 掉落与结算界面需明确展示资源来源与去向。
- 音频反馈:
  - 关键成长事件（升级、里程碑解锁、高稀有掉落）有高辨识反馈。
- UI 提示:
  - 结算面板应展示“距离下个里程碑还差多少”。
- 失败后纠偏提示:
  - 当资源不足或购买失败时，给出明确原因与替代路径。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - 前期强调经验、天赋点、基础掉落三条线的关系。
- 第一次失败学习点:
  - 玩家理解“高风险任务收益更高，但也更需要资源预留”。
- 中后期进阶点:
  - 通过章节与据点倍率掌握资源路线规划。

## 8) 核心参数区间（最小/推荐/最大）

- 掉率倍率（全局）: `0.5 / 1.0-1.2 / 1.8`
- 任务奖励倍率（主线）: `1.0 / 1.15-1.3 / 1.5`
- 商店价格倍率: `0.8 / 1.0 / 1.3`
- 里程碑间隔（击杀/连击/通关）: `短 / 中 / 长`（按章节递进）

## 9) 验收标准（量化）

- 指标 1（配置完整性）:
  - Growth/Economy Config Gate 全通过，且无阻塞项。
- 指标 2（奖励路由正确性）:
  - 任务/关卡/里程碑奖励均通过专项回归，链路一致。
- 指标 3（边界稳定性）:
  - 商店购买在库存异常与上限场景下不出现扣费错误。
