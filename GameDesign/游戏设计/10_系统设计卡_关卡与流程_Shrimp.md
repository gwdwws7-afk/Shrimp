# 系统设计卡：关卡与流程（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Level
关联 DDR-ID: `DDR-2026-03-24-04`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 在 15-22 分钟内完成一关的“教学 -> 升压 -> 峰值 -> 结算”体验闭环。
  - 在据点事件和 Boss 战之间形成可学习、可复盘的推进节奏。
- 系统边界（与其他系统接口）:
  - 上游: `LevelData`、任务系统、波次/事件系统。
  - 下游: Boss 出场门控、结算与成长反馈、章节推进。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 我在一场持续升级的海底战役中，不断推进战线并完成关键目标，最终以 Boss 战收束本关高潮。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 识别当前目标 -> 清理一轮敌群 -> 获得短反馈（掉落/提示/目标进度）。
- 3 分钟循环:
  - 据点小目标完成 -> 事件变体切入 -> 强度抬升 -> 资源回补 -> 进入下一个据点节点。

## 4) 关键规则与约束

- 规则 1:
  - 每关固定“两据点 + 事件波次 + Boss Gate + 结算”的主流程骨架。
- 规则 2:
  - 每关至少包含 1 条主线目标与 1 个可感知事件变化，避免纯清怪流水线。
- 规则 3:
  - 关卡时长目标区间 15-22 分钟，Boss 战时长目标 3-5 分钟。
- 关键约束（性能/输入/资源/时序）:
  - 维持既有运行门禁（LevelData/LevelContent/CombatDensity）稳定通过。
  - 当前阶段不引入新核心逻辑，仅通过内容配置和流程脚本提升体验密度。

## 5) 决策点与风险回报

- 主要决策点:
  - 事件优先级（援军/追击/占点/保护）的处理顺序。
  - 资源保留 vs. 快速推进（技能、消耗品、无双节奏）。
- 失败代价:
  - 任务失败/保护目标破坏导致波次压力上升，形成时间与资源惩罚。
- 成功收益:
  - 更稳定的推进节奏、Boss 前资源状态更佳、结算奖励更高。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 事件类型、目标状态、Boss Gate 开启状态必须有清晰提示。
- 音频反馈:
  - 事件切换、据点完成、Boss 出场应有明显音频层次区分。
- UI 提示:
  - HUD 仅保留“当前主目标 + 关键风险提示”，降低噪声。
- 失败后纠偏提示:
  - 在失败结算中明确展示失败原因（目标被破坏/超时/Boss 关键机制未处理）。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - L01-L02 强化据点与事件语法（占点、保护、援军）识别。
- 第一次失败学习点:
  - 保护目标与追击事件中，学会“先解风险源，再清场”。
- 中后期进阶点:
  - L06+ 通过复合事件和 Boss 联动考察战场优先级管理能力。

## 8) 核心参数区间（最小/推荐/最大）

- 单关总时长（分钟）: `15 / 18 / 22`
- 每关据点波次数（总计）: `6 / 8 / 10`
- 关键事件数（每关）: `2 / 3 / 4`
- Boss 战时长（分钟）: `3 / 4 / 5`

## 9) 验收标准（量化）

- 指标 1（流程完整性）:
  - 10 关均通过 LevelData/LevelContent/CombatDensity 三层校验，缺口为 0。
- 指标 2（节奏稳定性）:
  - 单关时长落在 15-22 分钟；Boss 战落在 3-5 分钟。
- 指标 3（内容差异性）:
  - 每关至少 1 个“主题机制差异点 + 事件差异点”并在设计卡中可追溯。
