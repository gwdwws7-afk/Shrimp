# 系统设计卡：美术资产（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Art
关联 DDR-ID: `DDR-2026-03-24-21`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 通过视觉识别快速理解敌我状态、关卡语义和目标优先级。
- 系统边界（与其他系统接口）:
  - 上游: 玩法与关卡需求（功能性优先）。
  - 下游: 角色/场景/UI/VFX/品牌素材落地与一致性验收。

## 2) 玩家核心幻想

- 玩家在海底世界中获得清晰、统一且具有辨识度的战场信息体验。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 识别关键对象 -> 做战斗决策 -> 接收视觉反馈。
- 3 分钟循环:
  - 通过场景与敌人变化感知关卡递进与风险升级。

## 4) 关键规则与约束

- 规则 1: 先满足功能可读，再强化风格化表现。
- 规则 2: Boss/UI/VFX 属于高优先补齐项。
- 规则 3: 各资产类型需有统一命名与验收标准。
- 关键约束:
  - 当前资产缺口较大，采用分批交付策略。
  - 与音效特效、UI、关卡节奏文档保持一致。

## 5) 决策点与风险回报

- 主要决策点: 功能美术优先级与风格强化时机。
- 失败代价: 信息表达不足、风格割裂、体验降级。
- 成功收益: 可读性提升、沉浸感增强、发布素材可用。

## 6) 反馈与可读性策略

- 视觉反馈: 关键机制对象（据点、弱点、危险区）必须高识别。
- 音频反馈: 与视觉层协同强调关键事件。
- UI 提示: 图标与视觉语义统一。
- 失败纠偏: 缺资产时保留可读占位规范。

## 7) 学习曲线与失败学习点

- 入门: 功能性美术先建立信息通道。
- 首次失败: 识别“读不懂”来自信息缺失还是机制不熟。
- 进阶: 在风格强化后仍保持读招和目标可读。

## 8) 核心参数区间（最小/推荐/最大）

- 功能资产覆盖率（%）: `60 / 80 / 100`
- Boss 资产完成度（%）: `30 / 70 / 100`
- UI 视觉资产覆盖率（%）: `40 / 75 / 100`
- VFX 关键反馈覆盖率（%）: `30 / 80 / 100`

## 9) 验收标准（量化）

- 指标 1: F/G 需求清单中高优先条目有明确交付状态。
- 指标 2: 关键玩法对象（Boss/据点/UI/VFX）满足功能可读验收。
- 指标 3: 资产命名与导入规范可通过清单审计。
