# 系统设计卡：多语言（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/Localization
关联 DDR-ID: `DDR-2026-03-24-12`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 在语言切换后，核心流程（战斗、任务、菜单、结算）可无障碍理解与操作。
  - 在任何场景下获得可读、无乱码、无关键缺词的文本反馈。
- 系统边界（与其他系统接口）:
  - 上游: UI 文案键值、任务与系统提示文本、设置存档。
  - 下游: 语言切换、回退策略、渲染显示、质量审计门禁。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 我可以随时切换语言，游戏信息仍然准确、清晰、不断流。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 读取关键提示 -> 做战斗或推进决策 -> 接收语言一致的反馈。
- 3 分钟循环:
  - 跨菜单/战斗/任务切换过程中，语言状态持续稳定且可回退。

## 4) 关键规则与约束

- 规则 1:
  - 核心模块必须 100% 键值覆盖，禁止关键路径缺词。
- 规则 2:
  - 语言切换必须即时生效，并具备英文回退兜底。
- 规则 3:
  - 所有可疑乱码/编码污染必须被质量门禁识别并阻断。
- 关键约束（性能/输入/资源/时序）:
  - 本轮以文档治理为主，不新增复杂运行逻辑。
  - 与 SaveManager 设置持久化行为保持一致。

## 5) 决策点与风险回报

- 主要决策点:
  - 键值命名规范、术语统一口径、回退优先级策略。
- 失败代价:
  - 文案缺失或乱码导致关键信息中断，直接伤害可玩性。
- 成功收益:
  - 降低理解门槛，提升跨语言用户的流程稳定性与体验一致性。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 语言切换后关键 UI 文本需立即刷新并保持布局稳定。
- 音频反馈:
  - 语言切换操作可给轻量确认反馈，避免误触不自知。
- UI 提示:
  - 设置界面明确展示当前语言与回退规则。
- 失败后纠偏提示:
  - 当键值缺失时显示可读 fallback，而非空文本或乱码。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - 首次进入设置时引导语言切换并验证即时生效。
- 第一次失败学习点:
  - 玩家可通过明显 fallback 文本识别缺词并继续游戏。
- 中后期进阶点:
  - 多语言与输入提示、任务文本、结算文本保持同口径演进。

## 8) 核心参数区间（最小/推荐/最大）

- 核心模块覆盖率（%）: `95 / 100 / 100`
- 可疑编码问题数（条）: `0 / 0 / 0`
- 语言切换生效时延（毫秒）: `100 / 250 / 500`
- 关键路径缺词数（条）: `0 / 0 / 0`

## 9) 验收标准（量化）

- 指标 1（覆盖率）:
  - 核心模块（MainMenu/LevelFlow/HUD/SkillBar/Quest/Talent/Economy/Boss）覆盖率达到 100%。
- 指标 2（质量）:
  - 本地化质量门禁通过，阻塞级问题为 0。
- 指标 3（稳定性）:
  - 语言切换、fallback、设置持久化回归全部通过。
