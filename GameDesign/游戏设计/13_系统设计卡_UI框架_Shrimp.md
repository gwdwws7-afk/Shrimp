# 系统设计卡：UI框架（Shrimp）

更新时间: 2026-03-24
版本: v0.1（文档优化轮）
Owner: Design/UI
关联 DDR-ID: `DDR-2026-03-24-07`

## 1) 设计对象

- 该系统服务的玩家行为:
  - 在高密度战斗中，快速读取关键状态并做即时决策。
  - 在关卡推进、任务、结算中持续获得清晰目标与反馈。
- 系统边界（与其他系统接口）:
  - 上游: 战斗系统、技能系统、任务系统、输入设备状态。
  - 下游: HUD、菜单、弹窗、提示系统与本地化文本展示。

## 2) 玩家核心幻想

- 玩家在该系统中“想实现什么”:
  - 在混战中依然“看得清、判断快、操作稳”，不被信息噪声淹没。

## 3) 30 秒到 3 分钟核心循环

- 30 秒循环:
  - 读血量/耐力/技能状态 -> 确认当前目标 -> 执行动作并接收命中反馈。
- 3 分钟循环:
  - 跟随任务与事件提示推进 -> 接受阶段反馈（据点完成/Boss Gate）-> 调整策略。

## 4) 关键规则与约束

- 规则 1:
  - HUD 只承载“即时决策必须信息”，非关键信息延后或弱化。
- 规则 2:
  - 同类语义的视觉和文字提示必须统一（战斗、任务、结算三端一致）。
- 规则 3:
  - 设备切换（键鼠/手柄）后提示文本与图标需在可接受时间内刷新。
- 关键约束（性能/输入/资源/时序）:
  - 本轮先做策划文档收口，不引入新 UI 逻辑。
  - 与统一输入层、手柄提示、本地化覆盖门禁保持一致。

## 5) 决策点与风险回报

- 主要决策点:
  - 哪些信息常驻、哪些信息按需出现（信息密度管理）。
  - 是否为不同设备提供差异化提示层。
- 失败代价:
  - 关键信息缺失或提示冲突，导致误判、误触和挫败感上升。
- 成功收益:
  - 战斗决策更快、任务推进更顺、失败后纠偏效率更高。

## 6) 反馈与可读性策略

- 视觉反馈:
  - 命中、受击、破防、终结四类反馈层次分明且不互相遮挡。
- 音频反馈:
  - 关键提示（低血、CD完成、任务更新）有清晰优先级。
- UI 提示:
  - Action Label、技能 CD、任务目标应统一语义与文案风格。
- 失败后纠偏提示:
  - 失败页显示核心原因与一条可执行改进建议。

## 7) 学习曲线与失败学习点

- 入门教学节点:
  - 新手阶段先教会玩家识别“资源条、技能可用、主目标”三大核心区块。
- 第一次失败学习点:
  - 玩家能从 UI 明确知道自己是“资源管理失败”还是“机制处理失败”。
- 中后期进阶点:
  - 在复杂事件和 Boss 战中，用最少提示支持高频决策。

## 8) 核心参数区间（最小/推荐/最大）

- HUD 常驻信息项（条）: `4 / 6 / 8`
- 战斗提示显示时长（秒）: `0.8 / 1.2 / 2.0`
- 设备切换提示刷新时延（毫秒）: `100 / 250 / 500`
- 屏幕同时高优先提示数（条）: `1 / 2 / 3`

## 9) 验收标准（量化）

- 指标 1（信息层级一致性）:
  - HUD、任务、结算三处关键术语与语义一致率达到目标（通过审计表）。
- 指标 2（可读性）:
  - 关键战斗提示（命中/受击/破防/终结）均有对应音画映射条目。
- 指标 3（设备适配）:
  - 键鼠与手柄切换后核心提示无错配或长时间滞后。

## 方法论对照区（必填）

- 00 总纲:
  - UI 支撑核心循环和反馈闭环，但表现层一致性文档仍不足。
- 01 MDA:
  - 机制与行为链可用，体验层短板集中在“信息噪声与反馈层级”。
- 02 FADT:
  - 意图到后果的可感知链路已建立，需进一步强化失败纠偏提示模板。
- 03 Lenses:
  - 主要风险为提示过载与语义不统一，已定义层级化与术语统一动作。
