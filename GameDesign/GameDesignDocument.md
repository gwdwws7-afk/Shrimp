## 3. 游戏核心概念

### 3.1 游戏名称
**中文**: 深渊猎手：异种肃清  
**英文**: Abyss Hunter: Xenocide

### 3.2 世界观设定（完整版）

**时代背景**: 公元2147年，人类启动深海能源计划“深蓝计划”，在马里亚纳裂谷深处进行高压钻探。钻探触发“裂潮门”开启，沉睡于深渊的异种生物机械文明被唤醒。

**异种文明（潮墓群）**:
- 形态: 生物与机械融合体，具备自我修复、共振通讯与群体进化能力。
- 组织: 以“母巢核心体”为中枢，通过“静潮圣所”传导群体意志。
- 目的: 夺回被深海封印的“深渊核”，驱动扩张与改造海床。

**人类阵营（深渊前线局）**:
- 组织: 深海前线局(PTA)负责清剿与情报回收。
- 技术: 逆向异种生物科技与深潜动力装甲。
- 战术: 孤军深入、点状据点清剿、短时窗口破防。

**关键资源**:
- 深渊珍珠: 异种能源结晶，可用于武器与天赋升级。
- 声潮共振: 异种群体通信网络，需通过据点破坏节点断链。

**主角定位**:
- 深渊猎手（代号: Starman）是前线局最强单兵，擅长高速斩击与群体压制。
- 任务: 回收失事研究站数据，切断共振网络，摧毁母巢核心。

**主线矛盾**:
人类必须在“裂潮门”完全开启前摧毁母巢核心，否则沿海城市将被异种改造为孵化巢床。

### 3.3 核心玩法循环
```
进入关卡 → 割草战斗 → 收集资源 → 升级能力 → 挑战Boss → 解锁新区域
    ↑                                                    ↓
    └──────────────── 重复强化 ────────────────────────────┘
```

### 3.4 核心体验支柱

| 支柱 | 描述 | 实现方式 |
|------|------|----------|
| **爽快感** | 一刀下去敌人成片倒下 | 大范围攻击、夸张击退 |
| **成长感** | 角色越来越强大 | 技能树、装备升级 |
| **新鲜感** | 每次游戏都有新敌人 | AI实时生成变异模型 |
| **挑战性** | Boss战需要技巧 | 阶段式设计、弱点机制 |

- `useRandomSpread`: 随机散射（霰弹）
- `spreadJitter`: 每发抖动角度（度）
- `usePredictiveAim`: 预测提前量
- `predictionFactor`: 预测系数
- `maxPredictionTime`: 最大预测时间（秒）
- 默认远程散射: 3发 / 12度

#### 群体AI节流与攻击令牌策略（当前实现）

- AI 决策间隔按附近敌人数扩展（默认：12 开始放慢，40 达到 2x；上限 0.25s）
- 攻击令牌上限动态放宽（默认：`maxActiveAttackers` + 附近敌人/6，上限 8）

#### 无双游戏设计 Skill（完整系统与流程）

**目标**：在高密度敌群中维持持续爽感，并确保关卡/经济/成长/UI形成稳定闭环。

**系统总览（模块 + 目的）**
- **战斗系统**：连段/击飞/破防/技能回转，保证爽感循环不断档。
- **敌群与AI**：敌群配比/AI节流/攻击令牌，保证密度与性能稳定。
- **关卡节奏**：据点→事件→精英→Boss Gate，构建高低起伏节奏。
- **经济循环**：消耗品/深渊币/珍珠掉落与商店闭环。
- **成长系统**：等级/天赋/珍珠/技能成长，强化中后期爽感。
- **任务系统**：主线/支线/挑战的结构化目标与奖励权重。
- **UI交互**：战斗信息可读、奖励反馈可视、操作引导不打断。

**流程模板（从关卡到回路）**
1) **进入关卡**：确认章节/难度/奖励倍率与Boss Gate条件
2) **据点序列**：Stronghold_01（节奏建立）→ Stronghold_02（强度提升）
3) **事件插入**：Reinforcement/Chase/HoldPoint/ProtectTarget 形成峰谷
4) **Boss Gate**：据点完成后刷Boss，破防窗口触发爆发
5) **结算回路**：关卡奖励 + 任务奖励 + 掉落回收 → 商店/天赋/珍珠配置

**关卡设计要点**
- 每关 2 个据点：第1据点建立节奏，第2据点拉升强度
- 每据点 3–5 波次：Wave1稳态，Wave2–3引入变体，Wave4以上高压
- Boss 出场延后：据点清完后触发，确保节奏完整

**经济循环要点**
- 掉落链：珍珠/消耗品/深渊币随关卡倍率与难度叠乘
- 商店节奏：在关卡间隔/据点间喘息提供补给与策略调整

**成长系统要点**
- 等级与天赋：提供技能回转/连段容错/破防效率等爽感增益
- 珍珠：绑定元素与技能倾向，形成中期build差异

**UI交互要点**
- HUD：连段/资源/破防窗口/弱点图标突出显示
- 任务：仅显示关键目标，不遮挡战斗节奏
- 奖励：结算时高亮“爽感提升项”（技能/珍珠/消耗品）

### 7.6 Boss战斗脚本模板（统一规范）

**目标**: 每个Boss 3-4 技能，2阶段，必含弱点/破防窗口。

**设计规范**
- 阶段1: 2-3个基础技能 + 1个节奏技能
- 阶段2: 2-3个强化技能 + 1个破防相关技能
- 破防窗口: 触发后 3-5 秒可打出高伤害
- 破防触发条件: 弱点破坏 / 特定技能中断 / 破韧槽清空

**Boss脚本结构建议**
```csharp
public class BossControllerBase : MonoBehaviour
{
    public enum Phase { Phase1, Phase2 }

    [Header("Phase")]
    public Phase currentPhase = Phase.Phase1;
    public float phase2HealthThreshold = 0.5f;

    [Header("Break Window")]
    public bool breakable = true;
    public float breakWindowDuration = 4f;
    public float breakCooldown = 12f;
    public float staggerMax = 100f;
    public float staggerCurrent = 0f;

    [Header("Skills")]
    public List<BossSkill> phase1Skills = new List<BossSkill>();
    public List<BossSkill> phase2Skills = new List<BossSkill>();

    [Header("Weak Point")]
    public Transform weakPoint;
    public float weakPointMultiplier = 2.0f;

    public void TickAI()
    {
        if (currentPhase == Phase.Phase1 && HealthPercent() <= phase2HealthThreshold)
        {
            EnterPhase2();
        }

        if (IsBreakWindowActive())
        {
            // Optional: slow time or lock to defensive behavior
            return;
        }

        BossSkill next = SelectSkill();
        if (next != null)
        {
            ExecuteSkill(next);
        }
    }

    public void ApplyStagger(float amount)
    {
        if (!breakable || IsBreakWindowActive()) return;
        staggerCurrent = Mathf.Min(staggerMax, staggerCurrent + amount);
        if (staggerCurrent >= staggerMax)
        {
            TriggerBreakWindow();
        }
    }

    private BossSkill SelectSkill()
    {
        // Weighted random with cooldown checks
        return null;
    }
}

[System.Serializable]
public class BossSkill
{
    public string id;
    public string name;
    public float cooldown = 6f;
    public float windup = 0.5f;
    public float active = 0.6f;
    public float recovery = 0.8f;
    public float damageMultiplier = 1.0f;
    public bool canTriggerBreak = false;
}
```

**破防窗口规范**
- 触发时播放破防提示与显著特效
- Boss进入短暂硬直/暴露核心
- 期间受到伤害提高 50-100%

**技能结构建议**
- 技能A: 控场 (拉扯/击退/区域限制)
- 技能B: 输出 (直线/扇形/大范围)
- 技能C: 机制 (召唤/护盾/弱点)
- 技能D: 阶段专属爆发

- **消耗品**: 直接入包（即时生效拾取），支持掉落表与敌人类型限制
- **深渊币**: 直接入账，支持掉落表与敌人类型限制

#### 掉率与倍率链路
- 基础掉率 × 关卡倍率 `LevelData.dropChanceMultiplier`
- × 难度倍率 `EconomyConfig.dropChanceDifficultyMultipliers`
- × 经济倍率（珍珠）：`EconomyConfig.pearlDropMultiplier`
- 消耗品/深渊币独立倍率与权重表（默认开启自动表）

#### 当前默认区间（可配）
- 珍珠掉率：基于敌人类型配置
- 消耗品掉率：0.12，数量 1（可按道具配置最小/最大堆叠）
- 深渊币掉率：0.35，掉落 4–8 深渊币

#### 任务奖励权重（主线/支线/挑战）

| 分类 | 代表任务类型 | 奖励倍率倾向（EXP/珍珠/深渊币） |
|------|--------------|-------------------------------|
| 主线 | CompleteStronghold / BossDefeat / CompleteWave | 1.15–1.3 / 1.15–1.3 / 1.2–1.4 |
| 支线 | Kill / KillEnemyType / Collect / Reach | 0.9–1.0 / 0.9–1.0 / 0.95–1.0 |
| 挑战 | Combo / BossBreak / Survive / Protect / CompleteWaveEvent | 1.05–1.15 / 0.95–1.1 / 1.05–1.15 |

> 具体倍率以 `EconomyConfig.questTypeMultipliers` 为准，可按关卡与难度叠乘。

- 任务分类字段：`QuestData.rewardTier`（Mainline/Side/Challenge）
- 叠乘顺序：QuestType → RewardTier → Chapter → Stronghold → 难度倍率 → 关卡倍率
- Chapter 曲线：`EconomyConfig.questChapterMultipliers`（按 `LevelData.chapterId`）
- Stronghold 曲线：`EconomyConfig.questStrongholdMultipliers`（按 `QuestData.targetStrongholdId` 或事件上下文）

#### C2 导入设置规范（压缩/采样率/通道）

**音频（SFX）**
- 采样率: 44.1kHz（短促 UI/SFX 可 22.05kHz）
- 声道: Mono（3D SFX 优先），UI 可 Stereo
- 压缩: Vorbis/ADPCM（二选一，短促用 ADPCM，长音用 Vorbis）
- Load Type: Decompress On Load（短促）/ Compressed In Memory（长音）

**音频（BGM）**
- 采样率: 44.1kHz
- 声道: Stereo
- 压缩: Vorbis
- Load Type: Streaming

**VFX（Prefab）**
- 纹理: 压缩格式按平台默认（移动优先 ASTC/ETC2，PC 默认即可）
- 粒子: GPU 粒子优先，限制发射速率与生命周期
- 贴图通道: 避免未使用的 Alpha 通道浪费

#### C3 命名校验清单

- 前缀必须正确: `SFX_` / `BGM_` / `VFX_` / `ENM_` / `UI_`
- 类别必须明确: `SFX_Skill_*` / `VFX_Enemy_*` / `BGM_L0X`
- 编号规范: 两位数起（`_01`, `_02`）
- 禁止空格与中文文件名
- 同一类资产保持命名风格一致
